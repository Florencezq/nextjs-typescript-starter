# H5 英语单词学习项目技术文档

## 1. 技术背景

本项目基于当前仓库的 Next.js 技术栈实现：

- Next.js 14 App Router
- React 18
- TypeScript
- Tailwind CSS
- NextAuth v5 beta，Credentials 登录
- PostgreSQL
- Drizzle ORM + `postgres` driver

当前项目已有邮箱密码登录和注册基础能力：

- `app/auth.ts`：配置 NextAuth Credentials Provider，使用 `getUser` 和 `bcrypt-ts` 校验密码。
- `app/auth.config.ts`：配置登录页和鉴权回调。
- `app/db.ts`：创建并查询 `"User"` 表，提供 `getUser` 和 `createUser`。
- `app/login/page.tsx`：邮箱密码登录页面。
- `app/register/page.tsx`：邮箱密码注册页面。

本技术文档基于 [docs/prd.md](/Users/florencez/Documents/ai-coding/nextjs-typescript-starter/docs/prd.md) 编写，目标是明确数据库、后端、前端、路由、状态和接口设计。

## 2. 核心技术目标

- 使用现有 `books` 和 `words` 表作为单词书与单词数据源。
- 扩展用户学习相关表，支持最近学习、学习进度、学习记录和单词详情。
- 复用现有邮箱密码登录注册逻辑，改造成 H5 Popup 登录注册体验。
- 前端采用 App Router 页面和 Server Actions，减少额外 API 层复杂度。
- 数据访问逻辑集中封装，避免页面组件直接拼 SQL。

## 3. 现有数据库表

## 3.1 `books` 单词书表

当前数据库已有 `public.books` 表，用于存储单词书元信息。

```sql
create table public.books (
  id bigint generated by default as identity not null,
  title text not null,
  word_count integer not null,
  cover_url text null,
  book_id text not null,
  tags text[] not null default '{}'::text[],
  created_at timestamp with time zone not null default now(),
  updated_at timestamp with time zone not null default now(),
  constraint books_pkey primary key (id)
) TABLESPACE pg_default;

create unique INDEX IF not exists books_book_id_unique
on public.books using btree (book_id) TABLESPACE pg_default;
```

### 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `bigint` | 数据库自增主键 |
| `title` | `text` | 单词书名称 |
| `word_count` | `integer` | 单词总数 |
| `cover_url` | `text` | 封面图，可为空 |
| `book_id` | `text` | 业务 ID，全局唯一 |
| `tags` | `text[]` | 标签 |
| `created_at` | `timestamptz` | 创建时间 |
| `updated_at` | `timestamptz` | 更新时间 |

### 使用场景

- 首页单词书列表。
- 最近学习卡片中的单词书标题与总数。
- 我的页面学习进度列表。
- 学习页顶部标题。

## 3.2 `words` 单词表

当前数据库已有 `public.words` 表，用于存储具体单词和完整 JSON 内容。

```sql
create table public.words (
  id bigint generated by default as identity not null,
  word_rank integer not null,
  head_word text null,
  content json null,
  book_id text null,
  constraint words_pkey primary key (id),
  constraint words_book_id_books_book_id_fk foreign KEY (book_id)
    references books (book_id) not VALID
) TABLESPACE pg_default;
```

### 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `bigint` | 数据库自增主键 |
| `word_rank` | `integer` | 单词在当前单词书中的排序 |
| `head_word` | `text` | 单词标题，例如 `adrift` |
| `content` | `json` | 单词完整内容 JSON |
| `book_id` | `text` | 关联 `books.book_id` |

### 使用场景

- 学习页读取当前需要学习的单词。
- 详情页读取完整 JSON 并渲染释义、例句、同近义词。
- 计算某本书的下一个单词。

### 建议补充索引

为了支持按单词书和排序高频查询，建议补充以下索引：

```sql
create index if not exists words_book_id_word_rank_idx
on public.words using btree (book_id, word_rank);

create index if not exists words_book_id_head_word_idx
on public.words using btree (book_id, head_word);
```

## 4. 需要新增的数据表

PRD 中需要支持以下用户学习能力：

- 用户最近学习的单词书。
- 用户在每本单词书中的学习进度。
- 用户点击「下一个」后的学习记录。
- 我的页面展示进度列表。
- 后续可扩展错词、收藏、复习计划。

本期建议新增 2 张核心表：

- `user_book_progress`：用户维度的单词书学习进度，一本书每个用户一条。
- `user_word_study_records`：用户单词学习记录，每次完成一个单词写一条或幂等更新一条。

如果本期希望实现更轻，也可以只建 `user_book_progress`。但为了后续统计和复习能力，建议两张表一起设计。

## 4.1 `user_book_progress` 用户单词书进度表

### 表定义

```sql
create table if not exists public.user_book_progress (
  id bigint generated by default as identity not null,
  user_id integer not null,
  book_id text not null,
  current_word_id bigint null,
  current_word_rank integer not null default 0,
  learned_count integer not null default 0,
  total_words integer not null default 0,
  status text not null default 'not_started',
  last_opened_at timestamp with time zone null,
  last_studied_at timestamp with time zone null,
  completed_at timestamp with time zone null,
  created_at timestamp with time zone not null default now(),
  updated_at timestamp with time zone not null default now(),
  constraint user_book_progress_pkey primary key (id),
  constraint user_book_progress_user_fk foreign key (user_id)
    references public."User" (id) on delete cascade,
  constraint user_book_progress_book_fk foreign key (book_id)
    references public.books (book_id) on delete cascade,
  constraint user_book_progress_current_word_fk foreign key (current_word_id)
    references public.words (id) on delete set null,
  constraint user_book_progress_user_book_unique unique (user_id, book_id),
  constraint user_book_progress_status_check check (
    status in ('not_started', 'learning', 'completed')
  ),
  constraint user_book_progress_counts_check check (
    learned_count >= 0 and total_words >= 0 and learned_count <= total_words
  ),
  constraint user_book_progress_rank_check check (current_word_rank >= 0)
);

create index if not exists user_book_progress_user_recent_idx
on public.user_book_progress using btree (
  user_id,
  last_studied_at desc nulls last,
  last_opened_at desc nulls last,
  updated_at desc
);

create index if not exists user_book_progress_book_idx
on public.user_book_progress using btree (book_id);
```

### 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `bigint` | 自增主键 |
| `user_id` | `integer` | 关联当前 `"User".id` |
| `book_id` | `text` | 关联 `books.book_id` |
| `current_word_id` | `bigint` | 最近完成学习的单词 ID |
| `current_word_rank` | `integer` | 最近完成学习的单词排序，未学习时为 `0` |
| `learned_count` | `integer` | 已学习数量 |
| `total_words` | `integer` | 单词书总词数，冗余保存便于展示 |
| `status` | `text` | `not_started`、`learning`、`completed` |
| `last_opened_at` | `timestamptz` | 最近打开学习页时间 |
| `last_studied_at` | `timestamptz` | 最近点击「下一个」完成学习时间 |
| `completed_at` | `timestamptz` | 完成整本书时间 |
| `created_at` | `timestamptz` | 创建时间 |
| `updated_at` | `timestamptz` | 更新时间 |

### 设计说明

- `current_word_rank` 表示「最近已经完成学习的单词」，不是当前正在看的单词。
- 下一个要学习的单词为：同一本书中 `word_rank > current_word_rank` 的第一条记录。
- 首次学习时 `current_word_rank = 0`，因此从第一条单词开始。
- `last_opened_at` 用于记录用户打开学习页，即使没有点「下一个」也可作为最近访问。
- `last_studied_at` 用于记录真实学习行为，也就是点「下一个」后。
- 首页「最近学习」建议优先按 `last_studied_at` 排序，其次按 `last_opened_at` 排序。
- `total_words` 从 `books.word_count` 初始化，展示时也可以与 `books.word_count` 对齐。

## 4.2 `user_word_study_records` 用户单词学习记录表

### 表定义

```sql
create table if not exists public.user_word_study_records (
  id bigint generated by default as identity not null,
  user_id integer not null,
  book_id text not null,
  word_id bigint not null,
  word_rank integer not null,
  study_count integer not null default 1,
  first_studied_at timestamp with time zone not null default now(),
  last_studied_at timestamp with time zone not null default now(),
  created_at timestamp with time zone not null default now(),
  updated_at timestamp with time zone not null default now(),
  constraint user_word_study_records_pkey primary key (id),
  constraint user_word_study_records_user_fk foreign key (user_id)
    references public."User" (id) on delete cascade,
  constraint user_word_study_records_book_fk foreign key (book_id)
    references public.books (book_id) on delete cascade,
  constraint user_word_study_records_word_fk foreign key (word_id)
    references public.words (id) on delete cascade,
  constraint user_word_study_records_unique unique (user_id, book_id, word_id),
  constraint user_word_study_records_count_check check (study_count > 0)
);

create index if not exists user_word_study_records_user_book_rank_idx
on public.user_word_study_records using btree (user_id, book_id, word_rank);

create index if not exists user_word_study_records_user_recent_idx
on public.user_word_study_records using btree (user_id, last_studied_at desc);
```

### 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `bigint` | 自增主键 |
| `user_id` | `integer` | 用户 ID |
| `book_id` | `text` | 单词书 ID |
| `word_id` | `bigint` | 单词 ID |
| `word_rank` | `integer` | 单词排序，冗余方便查询 |
| `study_count` | `integer` | 学习次数 |
| `first_studied_at` | `timestamptz` | 第一次学习时间 |
| `last_studied_at` | `timestamptz` | 最近一次学习时间 |
| `created_at` | `timestamptz` | 创建时间 |
| `updated_at` | `timestamptz` | 更新时间 |

### 设计说明

- 点击「下一个」时才写入或更新该表。
- 使用唯一键 `(user_id, book_id, word_id)` 保证同一用户对同一单词只有一条累计记录。
- 重复学习同一单词时，`study_count + 1`，更新 `last_studied_at`。
- 本期进度计算主要依赖 `user_book_progress`，该表用于后续学习历史、统计、复习和错词扩展。

## 6.1 核心数据方法

### `getBooksWithProgress(userId?: number)`

用于首页展示全部单词书。

未登录时只返回单词书基础信息。

已登录时返回单词书基础信息和当前用户进度。

```ts
type BookListItem = {
  bookId: string;
  title: string;
  wordCount: number;
  coverUrl: string | null;
  tags: string[];
  progress?: {
    learnedCount: number;
    totalWords: number;
    status: 'not_started' | 'learning' | 'completed';
    currentWordRank: number;
    lastStudiedAt: string | null;
  };
};
```

### `getRecentProgress(userId: number)`

用于首页「最近学习」模块。

```ts
type RecentProgress = {
  bookId: string;
  title: string;
  wordCount: number;
  learnedCount: number;
  totalWords: number;
  status: 'not_started' | 'learning' | 'completed';
  nextWord?: {
    id: number;
    headWord: string | null;
    wordRank: number;
  };
};
```

查询规则：

- 从 `user_book_progress` 中按 `last_studied_at desc nulls last, last_opened_at desc nulls last, updated_at desc` 获取最近一条。
- 关联 `books` 获取单词书名称和总数。
- 根据 `current_word_rank` 查询下一单词。
- 如果该记录 `status = 'completed'`，`nextWord` 可为空。

### `ensureBookProgress(userId: number, bookId: string)`

用于用户进入学习页前创建或读取进度。

规则：

- 如果已有 `(user_id, book_id)` 记录，更新 `last_opened_at` 和 `updated_at`。
- 如果没有记录，从 `books.word_count` 初始化：
  - `current_word_rank = 0`
  - `learned_count = 0`
  - `total_words = books.word_count`
  - `status = 'not_started'`
  - `last_opened_at = now()`

### `getNextWordForStudy(userId: number, bookId: string)`

用于学习页读取当前卡片。

规则：

- 先读取 `user_book_progress`。
- 如果无进度，调用 `ensureBookProgress`。
- 查询 `words` 中满足 `book_id = bookId` 且 `word_rank > current_word_rank` 的第一条。
- 如果不存在下一条，返回完成状态。

```sql
select *
from public.words
where book_id = $1
  and word_rank > $2
order by word_rank asc
limit 1;
```

### `completeCurrentWord(userId: number, bookId: string, wordId: number)`

用于点击「下一个」后保存进度。

处理步骤：

1. 校验用户已登录。
2. 查询当前 `wordId` 对应单词，校验 `book_id` 是否一致。
3. 写入或更新 `user_word_study_records`。
4. 更新 `user_book_progress`：
   - `current_word_id = word.id`
   - `current_word_rank = max(old.current_word_rank, word.word_rank)`
   - `learned_count = max(old.learned_count, word.word_rank)`，或基于已学习记录 count 计算
   - `status = 'learning'` 或 `completed`
   - `last_studied_at = now()`
   - `updated_at = now()`
5. 查询并返回下一单词或完成状态。

建议使用事务，避免记录表和进度表状态不一致。

## 7. 单词 JSON 解析规范

`words.content` 当前为完整 JSON。前端不应直接在每个组件里深层读取 JSON，建议在服务端统一转换为 View Model。

### 原始 JSON 关键路径

```ts
const wordContent = word.content?.content?.word?.content;
```

但根据 PRD 示例，数据库中的 `content` 可能保存的是完整外层对象，也可能保存的是 `content` 字段内的对象。实现时需要先确认入库结构。建议兼容两种格式：

```ts
function getWordPayload(raw: any) {
  return raw?.content?.word ?? raw?.word ?? raw;
}
```

### 学习页 View Model

```ts
type StudyWordView = {
  id: number;
  bookId: string;
  wordRank: number;
  headWord: string;
  ukphone?: string;
  usphone?: string;
  pos?: string;
  tranCn?: string;
  sentence?: {
    en: string;
    cn: string;
  };
};
```

### 详情页 View Model

```ts
type WordDetailView = {
  id: number;
  bookId: string;
  wordRank: number;
  headWord: string;
  wordId?: string;
  ukphone?: string;
  usphone?: string;
  phone?: string;
  translations: Array<{
    pos?: string;
    tranCn?: string;
    tranOther?: string;
    descCn?: string;
    descOther?: string;
  }>;
  sentences: Array<{
```

### 字段容错

- `head_word` 为空时，尝试读取 JSON 中的 `headWord` 或 `word.wordHead`。
- `trans` 为空时，学习页只展示单词和例句。
- `sentence.sentences` 为空时，学习页隐藏例句区域。
- `syno.synos` 为空时，详情页隐藏同近义词模块。

## 8. 后端架构

## 8.1 路由规划

```text
/                 首页
/mine             我的
/study/[bookId]   单词学习页
/word/[wordId]    单词详情页
```

### 页面职责

| 路由 | 类型 | 职责 |
| --- | --- | --- |
| `/` | Server Component | 读取 session、单词书列表、最近学习 |
| `/mine` | Server Component + Client Component | 读取 session、学习进度，承载登录注册 Popup |
| `/study/[bookId]` | Server Component + Client Component | 鉴权、读取当前学习单词、处理下一个交互 |
| `/word/[wordId]` | Server Component | 鉴权可选，读取单词详情 |

## 8.2 鉴权规则

### 公开访问

- `/`
- `/mine`
- `/login`
- `/register`

### 需要登录

- `/study/[bookId]`
- 用户进度相关 Server Actions

### 详情页鉴权

`/word/[wordId]` 可以有两种策略：

- 策略 A：公开可访问。适合单词详情作为开放内容。
- 策略 B：需要登录。适合严格围绕学习流程。

本期建议使用策略 B，避免未登录用户绕过首页点击限制直接进入学习内容。

## 8.3 Middleware 调整建议

当前 `app/auth.config.ts` 只保护 `/protected`。需要改为保护 `/study` 和可选的 `/word`。

建议逻辑：

```ts
const protectedPaths = ['/study', '/word'];
const isProtectedPath = protectedPaths.some((path) =>
  nextUrl.pathname.startsWith(path)
);

if (isProtectedPath && !isLoggedIn) {
  return false;
}
```

对于未登录访问 `/study/[bookId]`，可重定向到：

```text
/mine?auth=login&redirect=/study/[bookId]
```

这样可以自动弹出登录 Popup，并在登录成功后回到原目标页。

## 8.4 Server Actions

### `loginAction`

用于 H5 Popup 登录。

输入：

```ts
type LoginInput = {
  email: string;
  password: string;
  redirectTo?: string;
};
```

输出：

```ts
type ActionResult =
  | { ok: true; redirectTo?: string }
  | { ok: false; message: string };
```

实现要点：

- 复用 `signIn('credentials')`。
- Popup 场景建议关闭默认 redirect，避免错误时整页跳转。
- 登录成功后由前端 `router.refresh()` 刷新会话相关 UI。

### `registerAction`

用于 H5 Popup 注册。

输入同登录。

实现要点：

- 调用 `getUser(email)` 判断用户是否存在。

## 11. 学习进度算法

## 11.1 进入学习页

输入：`userId`、`bookId`

```text
如果没有 user_book_progress
  创建进度记录 current_word_rank = 0

更新 last_opened_at = now()

查询 words
  where book_id = bookId
  and word_rank > current_word_rank
  order by word_rank asc
  limit 1

如果查到单词
  展示该单词
否则
  展示完成状态
```

## 11.2 点击下一个

输入：`userId`、`bookId`、`wordId`

```text
查询当前 word
校验 word.book_id = bookId

upsert user_word_study_records

读取 progress

newCurrentRank = max(progress.current_word_rank, word.word_rank)
newLearnedCount = 查询该用户该书已学习不同 word 数量
或使用 max(progress.learned_count, word.word_rank)

如果 newLearnedCount >= totalWords
  status = completed
  completed_at = now()
否则
  status = learning

更新 user_book_progress

查询下一单词
返回给前端
```

### `learned_count` 计算建议

若单词书 `word_rank` 连续且从 1 开始，可以使用：

```text
learned_count = current_word_rank
```

若无法保证连续，建议使用：

```sql
select count(*)
from public.user_word_study_records
where user_id = $1
  and book_id = $2;
```

本项目的单词数据看起来有 `wordRank` 排序，但不应强依赖一定连续。技术实现建议使用 count 计算，更稳。

## 12. 事务与并发

点击「下一个」需要在事务内完成：

- 写入或更新 `user_word_study_records`。
- 计算 `learned_count`。
- 更新 `user_book_progress`。
- 查询下一单词。

并发场景：

- 用户快速重复点击「下一个」。
- 用户多个页面同时学习同一本书。

处理策略：

- 前端按钮 loading 时禁用重复点击。
- 后端用唯一键 `(user_id, book_id, word_id)` 保证学习记录幂等。
- 更新进度时使用 `max(current_word_rank, word.word_rank)`，避免旧请求覆盖新进度。
- 如果要进一步严格，可在事务中 `select ... for update` 锁定该用户该单词书的 progress 行。

虽然 App Router 可以直接使用 Server Actions，本项目仍建议用接口式返回类型，方便前端处理。

## 15. 样式与 H5 适配

### 布局

- App 最大宽度：`max-w-[480px]`。
- 桌面端居中：`mx-auto`。
- 页面最小高度：`min-h-dvh`。
- 底部 Tab 高度：建议 `64px`，加 `env(safe-area-inset-bottom)`。
- 内容区域底部 padding：至少 `pb-20`。

### 组件建议

- 卡片圆角不超过 `8px`，保持工具型产品的简洁感。
- 按钮高度不低于 `44px`，适合移动端点击。
- 学习页避免过多装饰，突出单词、音标、释义和例句。
- 长单词、长例句需要允许换行，不应溢出容器。

## 16. 安全设计

### 登录注册

- 密码继续使用 `bcrypt-ts` hash 存储。
- 不在前端返回用户密码字段。
- 登录失败统一提示，避免泄露邮箱是否存在。
- 注册时邮箱已存在可以明确提示，因为这是注册流程的正常反馈。

### 数据访问

- 所有进度读写必须从 session 中获取 `userId`，不能信任前端传入的 userId。
- `bookId` 和 `wordId` 必须在服务端校验关系。
- `redirect` 参数需要限制为站内路径，避免开放重定向。

### JSON 渲染

- `words.content` 中内容作为文本渲染，不使用 `dangerouslySetInnerHTML`。
- 如果未来展示富文本，需要先做 HTML sanitize。

## 17. 性能设计

### 查询优化

- 首页单词书列表只取 `books` 和进度摘要，不取所有 `words.content`。
- 学习页只取当前一个单词。
- 详情页才读取完整单词 JSON。
- `words(book_id, word_rank)` 是学习流程关键索引。
- `user_book_progress(user_id, last_studied_at, last_opened_at)` 是最近学习关键索引。

### 渲染优化

- 首页和我的页优先 Server Component 渲染。
- Auth Popup 和学习卡片交互使用 Client Component。
- 单词详情页可以 Server Component 渲染，减少前端 JS。

### 数据层

- `getBooksWithProgress` 未登录时不返回用户进度。

### 页面层

- 首页未登录态符合 PRD。
- 首页已登录无进度时不展示最近学习。
- 首页已登录有进度时展示最近学习。

## 20. 风险与注意事项

- 当前 `"User"` 表使用大写表名且需要双引号，SQL 和 Drizzle schema 必须保持一致。
- `words.content` 的 JSON 层级需要用真实数据确认，解析函数要做容错。
- `words.book_id` 外键当前为 `not VALID`，历史数据可能存在无效关联，查询时需要处理空结果。
- `books.word_count` 与实际 `words` 数量可能不一致，进度展示建议以 `books.word_count` 为主，异常数据可在后台脚本校验。
- NextAuth v5 beta 的 `signIn` 在 Server Action 中的重定向和错误行为需要实测，Popup 场景要避免整页跳走。
- 当前 `auth.config.ts` 会把已登录用户从非 protected 页面重定向到 `/protected`，实现 H5 主页前需要调整这段逻辑，否则已登录用户访问 `/` 或 `/mine` 可能被错误跳转。

## 21. 验收标准

- 数据库新增表可以支持每个用户、每本单词书独立保存进度。
- 首页可以基于 `books`、`words`、`user_book_progress` 渲染所有 PRD 状态。
- 未登录学习入口可以通过 `/mine` 登录 Popup 完成闭环。
- 登录注册复用现有邮箱密码认证逻辑。
- 学习页可以准确从最近完成单词的下一个开始。

- 我的页可以展示用户邮箱、退出登录和学习进度。
- 单词详情页可以从 `words.content` 渲染完整学习信息。
